# Utterleaf code and usability review

> Historical review, September 8, 2026. Working-tree and test-status statements
> below describe that review. See [current documentation](README.md) and
> [platform testing](platform-testing.md) for today's behavior and validation.

Reviewed the source checkout on Windows on September 8, 2026. This pass covered
recording and transcription handoffs, hotkeys, paste and edit delivery, settings,
and the existing regression suite. Changes are in the working tree.

## Findings fixed

| Priority | Trigger and previous behavior | Change |
| --- | --- | --- |
| High | Start another take before the 160 ms recording tail finishes. Harvesting treated a reserved worker as an active decode, potentially leaving audio queued forever and changing the paste target. | Preserve the release-time tail arguments and start its worker correctly. |
| High | A previous decode finishes during the next take's recording tail. The next take could be queued after the only worker exited. | Synchronize queue handoff and start a worker when the previous decode has finished. Keep the busy indicator while a tail is pending. |
| High | Several short takes finish while a slow decode runs. The single pending slot overwrote an earlier take. | Preserve additional takes in FIFO order; cancellation clears the backlog. |
| High | Copy something while Utterleaf is restoring the clipboard. The saved clipboard overwrote the newer copy. An unreadable original clipboard was restored as empty text. | Restore only when the original was read successfully and the clipboard still contains the dictated text. |
| High | A spoken edit could undo a manual change or act in the wrong field. | Replace blind Undo with verified, scoped native-field replacement. Unsupported or changed fields use manual recovery. Verify the resulting text before reporting success. |
| Medium | Press an unrelated key while a toggle shortcut remains held. Recording toggled again. | Trigger only when the shortcut transitions from released to pressed. |
| Medium | Generate GPU setup instructions before running diagnostics. Save report remained disabled; a later failed check could leave it enabled. | Keep export availability synchronized with the current report. |
| Low | First-time users see “Keep going” without an explicit instruction to release or press again. | Explain the complete gesture, update instructions with mode, and wrap the card text in compact windows. |

The clipboard polling loop also now uses the same monotonic clock for its start
and deadline comparison.

## Follow-through on the remaining findings

1. **Edit safety:** `edit_target.py` verifies the native field identity, complete
   text, and caret against a receipt of the original paste. It selects only that
   insertion, verifies the selection, replaces it, then checks the result.
   Standard Unicode Windows Edit controls are supported. Changed fields,
   password/read-only fields, browsers, rich editors, and other platforms fail
   closed. Revised text is offered on the clipboard; standalone scratch asks
   for manual deletion. No generic Undo is sent. Field snapshots expire after
   20 seconds and are never logged. A hidden native Windows Edit-control test
   verifies actual messages, Unicode replacement, and restoring the original
   selection. This uses Microsoft's documented
   [selection](https://learn.microsoft.com/en-us/windows/win32/controls/em-setsel)
   and [replacement](https://learn.microsoft.com/en-us/windows/win32/controls/em-replacesel)
   messages.

2. **Recording limits:** capture is bounded at the configured duration (120
   seconds by default); an automatic stop announces the limit and resets toggle
   mode. A stale timer cannot stop a newer take. Four pending takes are accepted
   behind the active decode; more are refused before opening the microphone,
   with an explanation. Audio is no longer silently sliced after release.

3. **Partial saves:** configuration, vocabulary, and startup files use atomic
   replacement. Save failures name the completed, failed, and unattempted steps.
   Successfully saved settings are sent for reload; the form stays available
   for retry. This is explicit partial-success handling, not cross-file rollback.

## Consumer experience improvements

- The microphone opens for a take and closes after its ending buffer or cancel.
  Startup no longer keeps a microphone stream open. The listening signal follows
  a successful microphone open. This removes idle capture; microphone startup
  latency now needs measurement on real devices.
- Tray artwork is rendered once per state before hotkey registration. A local
  five-update probe took 4.440 seconds before caching and 0.000041 seconds with a
  warm cache afterward. These are icon-update measurements, not STT benchmarks.
- Dictated content was removed from debug logging. Telemetry-disable and implicit
  account-token-disable flags override inherited environment settings.
- The Dictation page loses duplicate introductory copy and the redundant shortcut
  section, bringing the shortcut and microphone controls closer to the top.
- Error messages point to Settings diagnostics rather than requiring users to
  interpret logs. Older status timers cannot dismiss a newer result.

## Remaining release work

Automatic editing in modern browsers, rich editors, macOS, and Linux still needs
platform adapters; manual recovery is deliberate until those can verify fields.
Ordinary paste still uses OS keystroke dispatch and cannot prove application
acceptance or detect every same-window field change. Clipboard restoration is
text-based; rich clipboard formats need separate validation and support.

Measure real microphone startup, end-to-end latency, recognition accuracy,
resource use, and idle behavior on reference devices. Verify accessibility,
packaged installers, and native desktop integration before a broad release.
The consumer acceptance criteria are in [consumer-experience.md](consumer-experience.md).

## Usability and validation

- Baseline: **226 passed, 1 skipped**. Current full suite: **269 passed, 1 skipped**, using
  `.venv/Scripts/python.exe -m pytest`.
- Added regression cases for rapid restart, decode completion during a tail,
  multiple pending takes and cancellation, accidental toggle activation,
  clipboard ownership, verified field edits, microphone release, automatic limits,
  bounded backlog, partial saves, atomic writes, privacy defaults, and cached icons.
- Generated real Tk screenshots with `tests/capture_settings.py` and visually
  inspected Dictation, Vocabulary, Voice commands, Engine, Help & diagnostics,
  and the compact 760 × 560 Dictation layout. Regenerated screenshots after the
  instruction change. The persistent Save/Close footer remains accessible;
  compact content intentionally scrolls.
- Existing widget tests verify preservation of edits across pages, saving a
  snapshot while later edits remain unsaved, preview behavior, and declining
  discard on close. Audio-device operations used mocks; file failure tests used
  temporary files, and the native field test used a hidden test-owned control.
- No personal settings were changed by screenshot capture. Screenshots are in
  the ignored `artifacts/screenshots/` directory.
- Live microphone accuracy, native paste/undo behavior in external editors,
  extended concurrency stress, screen-reader behavior, packaged executables,
  and macOS/Linux desktop integration were not exercised in this pass. No
  release was built or published.
